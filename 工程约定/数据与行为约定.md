# 数据与行为约定

适用于2.2新版源码。真实数据库、已安装协议及服务的切换另按[人工切换记录](../项目文档/验证记录/04-设计2.2实现与人工切换.md)执行；源码状态不代表验收通过。

- Markdown `assets/`正式，`inbox/`候选。新增确认绑定确切相对路径和原始字节Hash；修订另绑定Asset ID与正式基线Hash，保留原身份和现有确认边界。普通工程授权不是正式确认。
- YAML仅解析为数据，复用现有Frontmatter校验；目录、Scope、Workspace、身份和Symlink资格不可绕过。Hash不规范化换行或Unicode。CURRENT/PREVIOUS保留用于治理，不通过PREVIOUS提供模型旧正文。
- 可信宿主按路径段最长匹配cwd项目，并合并用户明确配置knowledgeAccess=PREAUTHORIZED的项目，原子签发WorkspaceCapability，最多8个不同项目，超限整批失败。默认HOST_ONLY；路径、别名、说明不授予权限。摘要持久化、无TTL；cwd来源沿用旧映射Hash，额外预授权来源Hash绑定PREAUTHORIZED状态，关闭后失效，恢复相同配置可重新有效；永久撤销仍删除指定摘要。元数据变更不撤销，无关映射不统一撤销，配置损坏或歧义拒绝。自动识别与真实交付须另行人工验证。
- 每次显式选择0–N能力，[]仅GLOBAL。任一无效能力整次拒绝；不保存最近Workspace，不从模型workspace/cwd获取权限。模型接口与人工全库Hub分离。
- 正常召回唯一入口knowledge_recall。项目业务实现、表/接口、故障、历史判断与重要工程选择自动触发Recall Skill；名称、别名、说明和请求语义用于选择已有能力，范围歧义才澄清，普通冻结实施不机械召回。Query为当前简洁检索表达；Kind只影响可选Scenario，场景每次显式激活，未证实净收益保持禁用。基础Query无场景仍可工作。
- 同一次调用采用有效配置和策略快照。候选先当前资格、按Asset去重合并原因，再分DIRECT/Query两桶；目标4/4不足回流，总数8。先最小引用再摘要升级，完整响应5000 Unicode code points，元数据也计入。DOCUMENT/SKILL仅引用，不改变来源桶。
- Recall操作/条目同事务。Read与Used各自记录事实；仅SQLite事实写错误可让Recall/Read降级继续交付，usageRecorded=false且无本次稳定引用。权限/资格/Hash/大小错误不可伪装为计数失败。
- Read当前Hash必须满足引用或expectedContentHash；Used校验来源/当前范围、身份和资格，不比较当前Hash与旧交付Hash。来源幂等，关联Read归一到原RecallItem，直接Read独立；totalUsedCount按assetId累计，不按Hash分桶。
- Usage不外键到能力、可重建Catalog或旧业务表。来源与授权快照不可由当前元数据重算。旧聚合不能转换为新事实。
- Schema显式离线升级到2，新链不构造旧表；人工基础验收后方可显式退役旧三表到3。保留知识原件、Inbox、Catalog/FTS、双版、能力和新事实，不整库重置。当前确认/Diff支持版本1/2/3。
- Hub/REST仅GET，不写Usage；保留回环及Host/Origin。正常服务启动、源码构建或实现授权不包含部署、真实迁移、删除或协议切换。
- 知识模板见[知识内容模型](知识内容模型.md)。Native Memories与正式知识互补，不自动同步或合并计数。
