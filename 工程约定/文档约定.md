# 文档约定

本约定适用于需要新建、修改、移动或归档项目文档的任务，不要求每项工作额外生成设计、计划或验证报告。

## 目录与命名

- 根目录 `工程约定/` 与 `项目文档/` 保持同级：前者保存长期规则，后者按类保存设计、审查、验证与历史方案，通过 [文档索引](../项目文档/文档索引.md) 导航。不再新建平行的 `docs/`、根目录 `设计文档/` 或其他文档汇总目录。
- 目录和文件名使用简洁、明确的中文。协议名、产品名和已有任务编号可保留，例如 `02-真实Desktop验收记录.md`、`03-双版确认与Diff验证.md`。
- 根目录 `README.md`、`AGENTS.md` 以及确有就地使用需要的模块 `README.md` 保留标准名称；源码、配置、fixture 和工具要求的文件名不按本文改名。
- `项目文档/` 各分类目录内的文档独立编号，从 `01` 开始，按 `01-中文名称.md`、`02-中文名称.md` 递增；分类目录本身不加编号，根目录导航文件 `项目文档/文档索引.md` 不加编号。
- 新文档使用所在分类现有最大序号加一，至少两位、不足补零；已有文件不因插入、删除或重排而整体重新编号，不重复使用已有序号。跨分类移动时采用目标分类的下一序号，并同步引用。
- 本次存量文件按文档索引中的顺序编号；已有 N00、F01、W01 等任务编号保留在中文名称中，不替代文件排序序号。
- `工程约定/` 下的文档不加序号，例如 `数据与行为约定.md`、`验证约定.md`、`文档约定.md`。
- 相同主题默认维护同一份文档，只有需要保留独立版本或原始审计证据时才另建文件，并注明关系。
- 文件名与正文版本一致；小幅补充不必新增版本。明确升级文档版本并改名时，同步引用与索引，不复制出多个无法判断现行性的“最终版”。

| 目录 | 内容 |
|---|---|
| `工程约定/` | 长期适用的项目规则，根目录 AGENTS.md 仅保留关键摘要和按主题阅读入口 |
| `项目文档/设计方案/` | 当前设计、经确认的实施方向、修复计划；未来方向必须明确标识，不等于实施授权 |
| `项目文档/审查记录/` | 设计审查、代码审计、问题核查与修复复核记录 |
| `项目文档/验证记录/` | 需要单独保存的实验、兼容性与验收证据；仍需维护的实验代码就近保留在相关模块，已结束的独立实验可清理并标注历史引用 |
| `项目文档/历史方案/` | 已明确被替代的设计和迁移方案，保留原内容供追溯，不作为现行实现依据 |

## 内容与证据

- 默认用中文编写新增叙述；代码、命令、标识符、原始错误和引用保留原文。历史文档不为统一语言而全篇翻译或改写证据。
- 设计先说明背景、目标、范围和关键决策，再按需要展开数据、接口、流程、异常与验证；不机械拆分概要设计与详细设计。
- 审查与验证记录注明日期、对象或基线、范围、发现、证据与未验证项；清楚区分需求已确认、代码已实现、自动测试通过、人工复核和真实环境验收。
- 历史审计中的状态、结论、行号和日志是当时的证据，不因后续修复改写为通过。记录新结论时说明其对应代码和验证时点，历史行号不能当作当前源码位置。
- 执行已有编号任务时遵循其任务记录约定；一般文档整理不更改任务完成状态，不触发迁移或真实知识确认。
- 当前使用方式维护在根目录 README；工程约定、设计和审查记录按职责链接，不重复维护整段配置说明或多份命令清单。

## 链接与整理

- 文档导航使用相对 Markdown 链接；源码证据可以使用仓库根相对路径，必要时附行号。不要为新导航写入个人电脑绝对路径；历史外部证据路径保留并注明其仓库外属性。
- 改名或移动前核对已有修改与目标重名，保留当前内容；同步仓库内的导航、文档引用和相关入口。仅修改路径引用时不顺带重写历史结论。
- 被替代方案移入历史目录后，在索引中标明历史属性及现行替代；不把尚未实施的方案仅因未完成就归档。
- 新增、移动或归档文档时更新文档索引。工程约定新增主题时同步根目录 AGENTS.md 的按主题阅读表，避免要求每次读取全部规约。
- 交付前检查文件完整性、链接目标、旧路径残留、中文命名与 `git diff --check`；新文件另做直接检查。文档整理无需为形式完整运行全套业务测试。
