# 知识内容模型

MEMORY／DOCUMENT／SKILL 的唯一正文与审阅模板入口。机器字段以 `apps/server/src/asset/schema.ts` 为准；以下章节不参与 Scanner 资格校验。

## 正文模板

ID 使用现有生成器；WORKSPACE 填已配置的 workspace，GLOBAL 省略该字段。`summary` 与当前结论一致，保留关键适用前提。

```markdown
---
id: <生成的ast ID>
type: MEMORY
scope: WORKSPACE
workspace: <已配置的Workspace>
title: <主题>
summary: <当前结论与关键适用条件>
---

# <主题>

## 当前结论
<可复用的判断>

## 适用条件
<环境、前提及需要重新评估的变化>

## 原因与取舍
<理由与代价，不编造备选方案>

## 依据与验证边界
- 来源：<原件链接，必要时注明版本或日期>
- 已验证：<实际验证的对象、方式和结果；未运行则注明>
- 未验证：<尚未核实的内容及边界>

## 本次变更说明
<仅更新时保留：改了什么、为什么改>
```

正文按需短写，模型推断和 Native 线索不算验证证据。类型差异：

- MEMORY 写判断，说明适用条件、原因与取舍。
- DOCUMENT 可沿用自然章节，交代适用性、来源和验证边界；没有决策时不编造取舍。
- SKILL 写触发、前置条件、步骤、验证及停止条件。

## 候选审阅展示模板

聊天正文按以下格式展示，字段间保留空行；细节留在完整候选中，默认不展示 Hash，不加文件 Emoji，不重复播报摘要。

```markdown
**<项目名或 GLOBAL> · 知识候选**

**【标题】** <知识标题>

**【摘要】** <一到两句核心判断及关键前提>

**【原因】** <建议新增／扩展／修订及增量理由>

[查看完整知识库候选](<Inbox候选文件的绝对路径>)

接受入库｜修改｜暂存｜拒绝
```

原因基于实际检索比较；未命中不等于全库不存在。展示前读取完整候选并保留路径、Asset ID、原字节 SHA-256；更新还绑定正式基线 Hash。接受针对完整候选，执行前复核 Hash，发生变化须重新展示确认。

### 选择框与等待

正文后在同一回合调用 `request_user_input_async`，问题只放短句，避免标题将换行压平：

```json
{
  "questions": [{
    "title": "如何处理这条知识候选？",
    "options": ["接受入库", "修改", "暂存（保留文件）", "拒绝（删除候选）"]
  }]
}
```

| 选择 | 操作 |
|---|---|
| 接受入库 | 复核 Hash，调用现行单文件确认 |
| 修改 | 按意见修改并重新展示；无具体意见则询问 |
| 暂存 | 只保留 Inbox 文件 |
| 拒绝 | 复核路径和 Hash 后直接删除该候选，无需二次确认；保留正式知识 |

弹框后用等待工具保持本轮等待，不发送最终回复（包括空回复）或重复进度。界面“进行中”表示等待反馈，不修改知识库 Task 状态。收到选择后执行；用户中断或另发问题时及时处理。预选、跳过、无回复、超时均不算接受，保留候选并结束本次等待，不反复弹框。之后可用文字继续处理，执行前仍须复核候选身份；多条候选时明确对应条目。无选项工具时退回文字。

2026-09-07 Desktop 实测：结束回合会使选择框消失，保持等待可完成选择。这是当前客户端适配，升级后可复核。
