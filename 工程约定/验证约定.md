# 验证约定

适用于实施验证、风险核验和构建检查。按受影响范围选择步骤，不是所有任务的固定执行清单；只读任务不自动执行实施测试。

## 按变更选择检查

- 改文件扫描/读取：覆盖非法 YAML、路径与 Frontmatter 冲突、重复 ID、父目录/末级 Symlink、文件移动或删除、旧 Catalog 下的当前资格；核对所有受影响入口。
- 改 Capability/Recall/Hook：核对持续授权、显式0–N选择、配置变化/撤销、当前资格、两桶配额及完整输出预算；宿主能力须单独人工验证，stdout保持Hook协议。
- 改 SQLite：核对事务、冲突/条件更新、索引差异、失败后可重试性和运行数据保留；不得直接用真实知识库或真实 SQLite 做故障注入。
- 改确认流程：在临时目录验证 Hash 不符、目标已存在、重复 ID、操作中断和源/目标状态；不执行真实候选确认来代替测试。
- 改接口或 Hub：核对输入 Schema、返回契约、错误映射、只读边界及 Host/Origin；界面变化需要实际渲染检查，测试 DOM 不等于浏览器验收。
- Server/ID 包使用 `tsx --test` 与 Node test runner；Hub 使用 Vitest/Vue Test Utils。复用临时目录、临时数据库与回环端口 fixture，按现有模式关闭资源并清理测试数据。
- 优先跑最小相关测试；修改编译入口、包导出、静态资源或启动装配时增加 build 和相关构建产物 smoke。需要验证 `dist` 时先重新构建，不能用旧产物证明新源码。
- 本地测试、构建 smoke、真实 Codex 客户端、浏览器和真实数据验收分别报告；未执行部分不宣称通过。规则/文档改动以引用、命令与差异核验为主，不为形式完整重跑业务全套测试。

## 命令

从仓库根执行，固定 Node.js `22.16.0`、pnpm `11.1.3`。以下表格中的 `pnpm ...` 统一通过 `npx -y -p node@22.16.0 -p pnpm@11.1.3 pnpm ...` 执行，避免复用其他 Node ABI 下的 SQLite 原生模块。

| 场景 | 命令 |
|---|---|
| 安装锁定依赖 | `pnpm install --frozen-lockfile` |
| 全仓类型检查 / 测试 / 构建 | `pnpm typecheck` / `pnpm test` / `pnpm build` |
| Server 测试 | `pnpm --filter @codex-memory-os/server test` |
| Server 单文件测试示例 | `pnpm --filter @codex-memory-os/server exec tsx --test --test-concurrency=1 test/asset-search.test.ts` |
| Hub 测试 | `pnpm --filter @codex-memory-os/hub test` |
| ID 包测试 / 构建 | `pnpm --filter @codex-memory-os/id-generator test` / `pnpm --filter @codex-memory-os/id-generator build` |
| 单包类型检查 | `pnpm --filter @codex-memory-os/server typecheck` 或 `pnpm --filter @codex-memory-os/hub typecheck` |
| REST / MCP 构建 smoke | `pnpm --filter @codex-memory-os/server smoke:rest:build` / `pnpm --filter @codex-memory-os/server smoke:mcp:build` |
| Hub / 确认构建 smoke | `pnpm --filter @codex-memory-os/server smoke:hub:build` / `pnpm --filter @codex-memory-os/server smoke:asset-confirm:build` |
| 端到端构建 smoke | `pnpm --filter @codex-memory-os/server smoke:n13:e2e:build` |
| Vite 代理 smoke | `pnpm --filter @codex-memory-os/hub smoke:proxy:dev` |
| 差异检查 | `git diff --check` |

命令表按影响范围选择，不是每次必跑清单。首次使用或 ID 包源码变化时，先构建 ID 包以更新其 `dist` 导出；全仓 build 按工作区依赖顺序构建。锁定安装失败先诊断版本与清单一致性，不重写 lockfile 绕过。运行 smoke 前读取其 fixture/环境处理，确认副作用限定于隔离目录和本地测试进程。


## 2.2 本轮静态检查边界

用户本轮明确不运行自动测试、隔离验证、smoke、浏览器或真实宿主验收。`pnpm --filter @codex-memory-os/server typecheck:source` 与 Hub 的同名命令仅检查生产源码，并直接解析共享ID源码，避免写入正在使用的dist。原有typecheck/test命令保留；历史测试仍引用退役协议，尚未迁入新版，不能作为新版检查结果。今后需要自动测试时先迁移相关fixture/断言，不能忽略这些旧引用错误声称全仓通过。
