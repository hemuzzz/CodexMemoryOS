## 2. 根因与最小修复

旧 `renderStoredTaskLoadout` 按冻结 Asset ID 调用 `findMetadata`，直接渲染 Catalog 的当前标题/摘要。保存时的合法性被当成以后所有同 ID 内容的访问资格：alpha MEMORY 合法迁到 beta 且 Catalog 完整刷新后，普通 Read 拒绝，Hook 却注入 beta 内容。MEMORY 合法变成 DOCUMENT/SKILL 时还继续沿用历史 DIRECT 注入摘要；删除或文件失效时可能输出旧 Catalog 摘要。

当前 `apps/server/src/loadout/service.ts:261` 起逐项调用纯 `AssetSearchService.read`，可信上下文仅取保存的 `task.workspace`。GLOBAL 可访问；WORKSPACE 必须与 Task 的单值 Workspace 相等；NULL Task 只允许 GLOBAL。`asset/search.ts:226` 的当前文件读取、`:706` 的范围判断以及 Scanner 的 F01/F02 边界继续复用。

本次 Read 返回的 **同一份 frontmatter** 提供 title、summary 和 type，随后没有再次查询 metadata。仅 `AssetNotFoundError` / `AssetNotAccessibleError` 被视为单项不可用，复用 Renderer 的 `assetMissing: true`，不提供该项动态标题、摘要或正文，继续合法兄弟项。配置不可用、数据库故障及程序异常传播；没有新增 catch-all。Renderer 原有超预算错误仍保留。

合格文件当前不再是 MEMORY 时，仅在本次投影副本中把历史 DIRECT 作为 ON_DEMAND 渲染；保留原 reason 等历史字段，提供合格标题和按需引用，不注入摘要。持久化 JSON、数组顺序、mode、Task Workspace、终态均不修改，不重新 Resolve、不搜索补位、不保存正文副本。

独立 Hook 在 `apps/server/src/hook/user-prompt-submit.ts:139` 接入上述入口。使用同一个已有 Repository 环境变量 `CODEX_MEMORY_OS_ASSET_REPOSITORY_PATH`，只在非空 Loadout 实际需要资格读取时建立只读 AssetSearchService；缺少该路径时安全报配置错误，不回退旧 metadata。空 Loadout 不调用 reader。只读连接关闭于本次调用结束；刷新回调为 no-op，索引继续由原主服务维护，没有 HTTP 化 Hook、第二套 watcher 或跨请求正文缓存。已有 Hook 配置需要为非空投影提供该路径，README 表格与命令示例已同步，未代用户修改个人配置。
